# SG Product Research

面向“中国供应链到新加坡”的零依赖选品研究项目。它把公开数据、可选 Monid 按次付费采集、原始证据、供应链假设和单位经济模型放进同一条可复现流程。

## 选品台的底层逻辑

### 第一问：为什么网站里是这些商品？

**当前网站没有从全市场筛出“40 个推荐选品”。它展示的是 9 个预设研究方向，以及其中“线缆整理”这一个方向下的 40 条历史商品链接样本。** 这两层数据不能混为一谈：

| 层级 | 目前是什么 | 由什么决定进入网站 |
|---|---|---|
| 研究方向 | 候选表中的 9 个方向，例如线缆整理、桌面收纳、包饰 | 首轮人工整理的榜单/截图线索和场景假设，不是自动全市场发现 |
| 商品样本 | Amazon 20 条 + Lazada 20 条，均围绕 `cable management` | 2026-09-06 对已选方向做的定向搜索采样，不是盈利排名前 40 |
| 研究建议 | 对 9 个方向给出的 WATCH、BLOCK 等 | 预设输入的参考评分、经济/风险规则和后续证据门槛；不是给 40 条链接逐件打采购分 |

所以，“为什么入选”和“入选后怎么评分”是两回事。**入池逻辑没有证据，后面的精细评分也不能证明选对了研究对象。** 当前更准确的产品定位是“定向选品研究台”，而不是已经完成验证的自动选品引擎。

### 1. 先定义要解决的生意问题

我们要检验的是：**面向新加坡的某类具体用户，有没有尚未被现有商品充分解决、且用户愿意付费的问题？我们能否用中国供应链，以可履约、可合规、可盈利的方式提供更合适的商品？** 不是先找到一个热度高的链接，再假定它值得卖。

首轮报告采用的研究偏好是“小、轻、尽量非强监管、容易演示价值的通用品”，目的是降低早期履约与试错负担。这是项目的初始搜索约束，不是这些品类一定有市场优势的证明。具体客群、销售平台、预算、履约方式和可接受亏损上限尚待业务方明确。

### 2. 9 个研究方向是怎么来的？

以下仅还原 [候选表](data/candidates.csv) 与 [首轮研究报告](docs/research-report.md) 中已有的线索，不补造完整的市场筛选历史：

| 方向 | 现有记录给出的入池线索 | 仍不能据此推断 |
|---|---|---|
| 通用桌面线缆整理套装 | 首轮报告记录 Amazon SG 电脑榜单的线缆保护线索，叠加轻小、通用、易演示的假设 | 不能证明组合套装比单件更好卖，或本地供给存在缺口 |
| 折叠桌面文件与设备收纳架 | Amazon SG 榜单出现桌面支架，延伸为桌面收纳方向 | 榜单支架不等于拟售折叠收纳架，产品匹配仍需验证 |
| 可替换挂件的通用包饰 | 截图中的包挂趋势，转化为原创/公版造型的研究假设 | 海外或截图热度不等于 SG 购买意愿，也不代表授权已解决 |
| 可折叠手持风扇 | 截图案例与新加坡高温场景推断 | 气候适配不等于低竞争；锂电运输、质量与退货未核实 |
| 通用吸尘器宠物毛发刷头 | 截图中的吸尘器配件线索 | 无法证明目标接口兼容、当地需求规模或退货可控 |
| 可重复使用衣柜防潮盒 | 新加坡湿热场景假设 | 场景合理不等于本地销量、复购或用户付费证据 |
| 旅行手账收纳补充套装 | Amazon SG 办公榜单的旅行笔记本线索 | 笔记本需求不能直接外推为补充套装需求 |
| 跨境保健补充剂 | Amazon SG 健康榜单线索，同时记录监管责任 | 入池不等于建议经营；目前被风险门槛阻断 |
| 热门 IP 角色毛绒挂件 | 截图中的 IP 趋势，同时记录缺少授权的问题 | 热度不能证明可合法销售；目前被风险门槛阻断 |

**目前没有完整的候选全集、统一入池标准、逐项排除理由或可复现的自动发现日志。** 因此，不能声称这 9 个方向优于所有其他方向；其中的风险对象保留在表中供否决与观察，也不等于推荐清单。截图和榜单线索的原始证据、类目与商品对应关系仍需补齐。

### 3. 为什么先研究线缆整理，为什么刚好 40 条？

现有首轮报告给出的理由是：线缆保护有榜单线索，而通用理线用品在轻小、可演示和避开电池等方面看起来适合低成本探索。**这只是“值得先验证”的先验判断，不是已证明它最赚钱。** 后续 40 条样本用于检查这个判断，不能反过来作为“初始选题已经科学”的证明。

记录中的采样过程如下：

| 项目 | 已记录事实 |
|---|---|
| 时间与关键词 | 2026-09-06，`cable management` |
| Amazon | 搜索页面前 20 条可见记录；保留 ASIN/标题/链接，只有前 8 条采到价格等指标；访问时配送地显示美国，不能确认 SG 配送条件 |
| Lazada | Best Match 搜索前 20 条；有价格和链接累计已售数，广告标识未观察到，不能称为已确认的自然结果或销量榜 |
| Shopee | 当时要求登录，没有取得对应样本，也没有绕过验证 |
| 样本数 | 两个平台各取 20 条的初步采样范围，20 + 20 = 40；不是模型根据获利能力筛到恰好 40，也不是统计代表性保证 |
| 样本用途 | 观察价格范围、已有供给、产品形态与竞争线索；线夹、套管、线槽、盒子和托盘不是同一规格，不能直接把混合中位价当成目标 SKU 的合理售价 |

来源：[Amazon 样本](data/samples/2026-09-06-amazon-cable-management.csv)、[Lazada 样本](data/samples/2026-09-06-lazada-cable-management.csv)、[访问与查询记录](data/samples/2026-09-06-marketplace-access.csv)。本轮说明依据已存档记录，不代表已重新抓取或验证当时的页面。

实现上，[research.py](src/sg_product_research/research.py) 读取这些历史 CSV，并把记录关联到 `cable-sleeve`；[cli.py](src/sg_product_research/cli.py) 读取预先准备的 9 个候选进行评分。**当前程序没有一个“从 Amazon/Lazada 全量商品中挑出 40 个好商品”的算法，也没有对这 40 条链接逐件完成利润与供应链核验。** Monid 接口接入尚未产生这些样本，它们来自此前的历史采样。

搜索前列受平台排序、时间、配送地区和可能的广告影响，是便利样本，不是随机样本；不同平台也可能对应相同货源或相似商品，40 条链接不等于 40 个独立商业机会。现有数据能说明某些形态和价格在采样时出现过，不能单独证明我们拟售商品存在未满足需求或可获利空间。

### 4. 补齐上游后，评分才有意义

应建立的完整链路是 **业务约束与客户问题 → 候选发现与入池理由 → 可复现的定向采样 → 同规格比较与反证 → 单位经济和风险门槛 → 小批量验证**。当前已实现的是后半段的记录、比较与规则检查；前半段仍主要依靠人工选题，没有完成系统性市场发现。

下一轮先明确候选从哪些类目、客群与问题产生，记录入池/排除理由，再对多个方向使用一致的关键词、地区、排序与样本范围进行比较。只有在这一步成立后，下面的评分才是有条件的辅助判断，而不是为先选中的方向补一个看似客观的分数。

### 5. 入池之后如何评估？

**模型来源说明：这是初版由 AI 助手按项目目标设计的启发式规则，不是论文、Monid 或电商平台提供的成熟预测模型。** 借鉴常见的单位经济核算、多指标加权打分和风险否决思路；具体权重、风险扣分、70/55 分界、20% 毛利和样本门槛都是项目初始假设，未经真实经营数据校准。测试通过只证明代码行为符合这些规则，不证明选品会盈利。

1. **证据**：商品和评论核对需求，社媒补充使用场景，正式供应商报价核对成本；保留来源、市场与原始日期。商品评价总数不是评论原文，公开挂牌不是正式报价。
2. **利润与评分**：当前估算的是单件贡献利润，不是净利润；仓储、末端履约、人力等尚未完整计入。售价除以 1.09 只适合相应的含税拆分情景，不能通用于所有经营主体。基础分按需求 25%、贡献毛利 25%、趋势 15%、物流 15%、竞争吸引力 10%、内容适配 10% 加权，再调整人工置信度与风险。导入证据不会自动修改人工分数或成本。
3. **硬门槛**：合规或 IP 风险至少 4，或贡献毛利低于 20%，直接 `BLOCK`；任何热度都不能抵消。
4. **研究准入**：30 天内至少 3 条 SG 商品、5 条 SG 评论、2 条社媒内容、1 份正式报价，并有两个独立需求平台。高分但证据不足仍为 `WATCH`，不是 `TEST`。
5. **实际验证**：`TEST` 只是进入 20-50 件测试的评估，采购前仍需样品、同规格三家报价、运输与合规复核；研究覆盖不等于市场成功概率。

完整计算公式和边界见 [docs/methodology.md](docs/methodology.md)。当前初始商品样本为 2026-09-06 的历史快照，不是实时行情。

## 评分模型的原型、变量和真实数据来源

### 1. 它在数学上属于什么模型？

当前模型不是销量预测、机器学习或经济计量模型，而是一个**带硬约束的加权和式多指标决策模型**（Weighted Sum Model / Simple Additive Weighting，WSM/SAW）：

```math
S_b=\sum_j w_jx_j
```

它先把需求、趋势、毛利、物流、竞争和内容展示能力统一写成 0–100 分，再按权重相加；随后乘以证据置信度系数，扣除合规与知识产权风险。合规/IP 风险过高或贡献毛利率过低时，不管总分多少都直接 `BLOCK`。因此更准确的结构是：

> **多指标加权排序 + 证据折减 + 风险扣分 + 经营硬门槛**

这种原型来自运筹学和多属性决策分析中的加性价值模型。Fishburn 的加性效用研究是其经典理论来源之一，但**本项目的六个维度、25%/15%/10% 权重、风险扣分和 70/55 阈值并不来自 Fishburn，也没有经过统计估计**，而是初版经营启发式。它成立还隐含三个较强假设：

1. 六项指标已经被可靠地转换到可比较的 0–100 尺度；
2. 每增加 1 分的价值在线性上相同；
3. 指标能够相互补偿，例如较高需求可以抵消一部分较差竞争环境。

当前数据并不足以验证这些假设，而且需求、趋势和短视频展示能力可能重复反映“热度”。所以总分适合用作**研究优先级排序**，不适合作为盈利概率或采购批准。

### 2. 每个变量现在究竟从哪里来？

最重要的事实是：**当前只有贡献毛利分 $`M`$ 是程序自动计算的；$`D/T/C/L/V`$、证据置信度和风险等级都是人工预填值。** 它们位于 [`data/candidates.csv`](data/candidates.csv)，由 [`model.py`](src/sg_product_research/model.py) 读取。程序目前不会从 Amazon、Lazada、Google Trends、TikTok 或 Monid 的网页/API 指标自动推导这些分数。

| 变量 | 含义与方向 | 当前如何产生 | 当前可追溯依据 | 更合理的后续量化方式 |
|---|---|---|---|---|
| $`D`$ | 需求强度，越高越好 | 人工写入 0–100 | `evidence_note`、`source_ids` 中的榜单/搜索线索；没有固定换算公式 | 固定市场、关键词和时间窗，结合 SG 销量代理、近期评论增量、排名持续性，并保留原始值与归一化规则 |
| $`T`$ | 趋势增速与持续性，越高越好 | 人工写入 0–100 | 截图、Google Trends 或 TikTok 线索；部分候选只有场景推断 | 使用 SG Google Trends 90 天/12 月变化、TikTok 多期指标和广告持续时间；区分短期爆发与持续趋势 |
| $`M`$ | 简化贡献毛利率转换出的分数，越高越好 | **代码自动计算** | 售价、采购成本、运费、汇率、平台费率、广告费率和退货损失率均来自候选 CSV；目前多数仍是待验证假设 | 用正式报价和真实账单建立悲观/基准/乐观情景，再用实际订单校准 |
| $`L`$ | 物流友好度，越高越好 | 人工写入 0–100 | 对重量、体积、电池、易损性等的主观判断；没有结构化子项 | 用计费重、体积、特殊运输、破损率、时效和末端履约成本形成明确子分 |
| $`C`$ | **竞争友好度**，越高表示越容易进入，并非“竞争越激烈分越高” | 人工写入 0–100 | 搜索结果数、价格带和卖家/广告线索的人工判断 | 使用同规格有效供给数、头部集中度、价格离散度、广告主数量及差异化空间；避免把广义搜索结果数直接当竞争强度 |
| $`V`$ | 短视频展示与解释产品价值的能力，越高越好 | 人工写入 0–100 | 对“前后对比、演示清晰度、视觉吸引力”的主观判断 | 先定义演示脚本，再观察 2s/6s 留存、CTR/CVR 和多素材复现；曝光不能替代成交 |
| $`E`$ | 证据置信度，0–100 | 人工写入；代码将其变成 0.70–1.00 的乘数 | 当前不等于页面的“近期证据覆盖率” | 根据来源独立性、地区匹配、时效、直接性和字段完整度建立透明规则，或用历史预测误差做校准 |
| $`R_c,R_{ip}`$ | 合规风险、知识产权风险，0–5，越高越危险 | 人工判断 | Customs/HSA/授权线索；风险至少 4 时硬阻断 | 按具体 SKU、HS 编码、认证、标签、商标/外观/专利和授权链逐项核验，保留专业意见与文件 |

[`research.py`](src/sg_product_research/research.py) 目前只把历史商品 CSV 和后来导入的 listing/review/social/supplier 证据进行归档、去重、时效与数量检查。如果某候选原始模型达到 `TEST`，但近期证据数量不够，它会把建议降为 `WATCH`；**它不会自动重算 $`D/T/C/L/V/E`$，也不会把网页数据转成分数。** 因此这些数字不是随机数，但也不是可复现的数据估计；更准确地说，是根据有限线索给出的人工先验分。

### 3. 利润公式的经济学原型是什么？

它的原型不是一套名为“含税售价保守模型”的经典模型，而是管理会计中的**单位贡献毛利**（unit contribution margin）：

```math
\text{单位贡献毛利}=\text{单位净销售收入}-\text{单位变动成本}
```

贡献毛利用于回答“多卖一件，在扣除随销量变化的成本后，还剩多少用于覆盖固定成本并形成利润”。它不同于最终净利润；固定费用、仓储、人力和资本占用等如果没有纳入，就不能据此断言整体业务盈利。OpenStax《Managerial Accounting》对贡献毛利、单位贡献毛利和贡献毛利率给出了标准定义与计算方法。

本项目代码实际计算为：

```math
\begin{aligned}
\text{到岸成本} &= \frac{\text{采购成本(CNY)}+\text{头程运费(CNY)}}{\text{CNY/SGD汇率}} \\
\text{净收入} &= \frac{\text{含税售价}}{1+9\%} \\
\text{比例变动成本} &= \text{含税售价}\times(\text{平台费率}+\text{广告费率}+\text{退货损失率}) \\
P &= \text{净收入}-\text{到岸成本}-\text{比例变动成本} \\
\text{贡献毛利率} &= \frac{P}{\text{净收入}}
\end{aligned}
```

其中，售价除以 1.09 只是“售价含 9% GST 且该主体需要按这一口径确认销项税”时的税前收入拆分。IRAS 确认新加坡当前 GST 税率为 9%，但是否应这样拆分取决于经营主体是否注册 GST、商品是否零税率/豁免、平台代征、进口方式和履约结构。**它不是进口 GST、关税和税务责任的完整模型，也不能天然称为保守模型。**

当前 `landed_cost` 实际只包含“采购成本 + 一项运费”，尚未完整包含进口 GST/关税、报关、仓储、末端履约、支付与换汇、包装、折扣、固定平台费、滞销和真实退货处置成本。因此这里更合适的名称是**简化贡献毛利情景**：拆出 GST 会降低表面收入，但漏掉其他成本又可能高估利润，两个方向不能互相抵消。

### 4. 以线缆整理套装为例，分数是怎么出来的？

`cable-sleeve` 在候选 CSV 中的主要输入为：$`D=88,T=55,C=24,L=92,V=82,E=86`$；采购成本 CNY 22、运费 CNY 10、售价 SGD 22.90、汇率 5.5，平台/广告/退货费率分别为 12%/15%/4%，两类风险均为 1。

按当前代码：

- 到岸成本：$`(22+10)/5.5=5.82`$ SGD；
- 税前净收入：$`22.90/1.09=21.01`$ SGD；
- 比例变动成本：$`22.90\times(12\%+15\%+4\%)=7.10`$ SGD；
- 单件贡献毛利：$`21.01-5.82-7.10=8.09`$ SGD；
- 贡献毛利率：$`8.09/21.01=38.5\%`$；
- 毛利分 $`M`$：以 40% 为人为满分锚点，得到约 96.3 分；
- 六项加权基础分约为 78.7，证据乘数为 $`0.70+0.30\times0.86=0.958`$；
- 再扣除合规风险 $`1\times4`$ 和 IP 风险 $`1\times6`$，最终为约 65.42 分，对应 `WATCH`。

这个算例说明最终结果看起来精确到两位小数，但其主要输入仍包含人工评分和成本假设；65.42 不应解释成“65.42% 的成功率”。

### 5. 参考来源与理论边界

- Peter C. Fishburn (1967), [Additive Utilities with Incomplete Product Sets: Application to Priorities and Assignments](https://doi.org/10.1287/opre.15.3.537)：加性效用/加权和式多属性评价的经典理论来源；不提供本项目的具体变量、权重和阈值。
- OpenStax, [Principles of Accounting, Volume 2: Managerial Accounting — Contribution Margin](https://openstax.org/books/principles-managerial-accounting/pages/3-1-explain-contribution-margin-and-calculate-contribution-margin-per-unit-contribution-margin-ratio-and-total-contribution-margin)：贡献毛利、单位贡献毛利和贡献毛利率的管理会计定义。
- IRAS, [Current GST rates](https://www.iras.gov.sg/taxes/goods-services-tax-(gst)/basics-of-gst/current-gst-rates)：新加坡当前 9% GST 税率及一般适用条件。
- Singapore Customs, [Import Procedures Overview](https://www.customs.gov.sg/doing-business/import-operations/import-procedures/import-procedures-overview/)：进口申报、许可、税费与留档的官方入口；具体商品仍须按 HS 编码和履约方式核实。

这些参考只能说明**模型组件有理论原型**，不能证明当前评分有效。要把它升级为可验证模型，至少需要：为每个变量定义原始指标与归一化公式、保存评分版本、做权重敏感性分析，并用真实试单结果检验排序与实际贡献毛利/周转表现的关系。

## 研究与采集工作流

- 候选证据面板：商品、评论、社媒、报价四类覆盖，30 天时效、地区隔离、来源链接和人工痛点标签。
- JSON/CSV 批量导入：逐批验证、去重、原子保存；错误证据可排除/恢复，保留原文。
- 历史数据：自动接入已有 Amazon/Lazada 40 条商品快照，保留原日期；Amazon 配送地区未复核，标为 `UNKNOWN`。
- Monid：动态发现接口、查看 Schema、报价预检、逐次批准、原始结果留档与显式字段映射。不假设所有平台都可访问。
- 决策纪律：证据不足的模型 `TEST` 降为 `WATCH`；不自动改成本或人工分数，不解除 `BLOCK`。

证据存储在 `data/evidence.json`（首次导入时创建）；私有采集任务在 `data/raw/monid/`，默认不提交。缺少密钥时仍可使用历史数据和文件导入。

### 启用 Monid

此项目使用 [Monid 官方 HTTP API](https://monid.ai/docs/api/overview)，不需要安装外部 Skill 或 CLI。先在 [Monid 控制台](https://app.monid.ai/access/api-keys)创建密钥。在你自己的 zsh 终端隐式输入，**不要发到聊天、页面或提交到 Git**：

```zsh
read -rs "MONID_API_KEY?Monid API key: "
export MONID_API_KEY
printf '\n'
PYTHONPATH=src python3 -m sg_product_research.server --port 8770
```

此时只开放接口发现和检查。要启用付费采集，先在 Monid 工作区设定预算与单次运行硬限额；确认设置后，停止本地服务，在同一终端运行：

```zsh
export MONID_ENABLE_RUNS=1
export MONID_WORKSPACE_CAP_CONFIRMED=1
export MONID_MAX_ESTIMATE_USD=0.25
PYTHONPATH=src python3 -m sg_product_research.server --port 8770
```

访问 [http://127.0.0.1:8770](http://127.0.0.1:8770)。`MONID_MAX_ESTIMATE_USD` **只是本地预估阈值，不是账单封顶**；公开 Run API 不提供单次金额硬限额参数。本地无法验证控制台限额，`MONID_WORKSPACE_CAP_CONFIRMED` 是操作者确认。每次执行仍需勾选批准，不自动充值、不定时采集、不自动发邮件。

按结果付费仅支持 Schema 中可识别的 1-10 条限制和单查询；复杂计费/嵌套参数需到 Monid 手工执行后导入。任务超时或状态未知不会自动重试，请先核对控制台账单和 run ID。首轮真实采集需要你的账号和余额；仓库测试使用模拟响应，不代表任何供应商已完成实测。

字段格式、映射和首轮研究清单见 [docs/data-playbook.md](docs/data-playbook.md)。
