先解释为什么研究这些商品，再讨论如何评分

初始数据是 9 个预设研究方向，以及线缆整理方向下的 40 条历史商品样本；不是从全市场筛出的 40 个推荐选品。当前仍缺少完整的候选发现与淘汰记录。

底层逻辑为什么入池 → 怎么采样 → 如何评估

第一问：为什么是这些方向和这 40 条样本？

  1. 先问客户问题，不先找高分商品

    目标是检验：新加坡哪类用户有未被现有供给充分解决、愿意付费的问题？我们能否用中国供应链，在可履约、合规且有利润的条件下提供更合适的商品？客群、预算与销售路径仍需明确。

  2. 9 个方向是初始人工研究池

    首轮把榜单/截图线索和新加坡场景假设整理成 9 个方向，偏好轻小、通用、易演示的商品。线缆/桌面/手账方向来自报告记录的榜单线索，包饰/风扇/刷头/IP 挂件来自截图线索，防潮盒含气候推断，补充剂来自健康榜单线索。

    这些线索只够提出问题，不能证明当地需求；保健品和 IP 挂件目前是风险阻断对象，留在研究池不等于推荐经营。完整候选全集、统一入池标准与排除记录尚未建立。

  3. 先选线缆方向，再做定向采样

    首轮报告给出的理由是线缆保护榜单线索，叠加轻小、通用、易演示的假设。这是优先研究理由，不是最赚钱的证明。2026-09-06 以 cable management 搜索，记录 Amazon 可见前 20 条与 Lazada Best Match 前 20 条，所以是 20 + 20 = 40。

    20 条是初步采样范围，不是算法筛选或统计代表性保证。Amazon 仅 8 条有价格等指标，配送地未复核；Shopee 当时要求登录，没有取得样本。搜索前列也不能当成销量榜或已确认的自然结果。

  4. 40 条是比较材料，不是采购清单

    它们都关联线缆整理方向，含线夹、套管、线槽、盒子、托盘等不同规格。价格与已售数用于观察已有供给，不能证明目标套装有市场缺口，也不能把混合中位价直接当目标售价。

    当前代码读取历史 CSV 和预设候选，不会自动遍历全市场发现机会，也没有给 40 条链接逐件核算利润。不同链接还可能来自相同或相近货源，不等于 40 个独立商业机会。

    核对 9 个方向的入池线索与原始文件

应补齐的完整链路：业务约束与客户问题 → 候选发现与入池理由 → 可复现的定向采样 → 同规格比较与反证 → 单位经济和风险 → 小批量验证。当前评分只发生在入池之后，不能弥补上游选题与样本偏差。

第二问：入池之后，如何评估？

项目自定的启发式评分，尚未验证预测能力

初版由 AI 助手按项目目标设计，借鉴常见的单位经济核算、多指标加权打分和风险否决思路；不是引用某篇论文、Monid 算法或平台推荐模型。具体权重和门槛尚未用真实经营数据校准。

用途是排列研究优先级，不是预测销量或赚钱概率。分数的小数位是计算精度，不是判断精度；代码测试通过也不代表商业有效性已被验证。

  1. 保留来源，不把热度当成交

    商品与评论验证需求，社媒补充使用场景，正式报价校验成本。每条证据保留平台、地区、日期和原文；公开挂牌不能代替供应商正式报价。

  2. 先算贡献利润，再看参考分

    假设单件贡献利润 = 售价 ÷ 1.09 −（采购成本 + 运费）÷ 汇率 − 售价 ×（平台费率 + 广告费率 + 退货损失率）。它不是净利润，仓储、末端履约、人力等成本尚未完整计入。

    除以 1.09 只适合对应的含税拆分情景，不是所有业务的通用税费扣除，也不保证一定保守；GST 注册、进口税和进项抵扣须另行核实。

    初始权重：需求 25%、贡献毛利 25%、趋势 15%、物流 15%、竞争吸引力 10%、内容适配 10%。这些比例体现项目偏好，没有数据证明比其他权重更优；毛利 40% 映射满分、70/55 分界及风险扣分也都是自定参数。

  3. 证据过期与风险门槛优先

    研究门槛：30 天内至少 3 条新加坡商品、5 条新加坡评论、2 条社媒内容、1 份正式报价，并覆盖至少两个需求平台。海外商品、过期或排除记录不计入本地近期需求；商品评价总数不等于评论样本数。

TEST
参考分 ≥ 70 且证据齐备，进入小批量测试评估，仍须样品、同规格三家报价与合规复核。
WATCH
参考分 55–69.99，或高分但缺少近期交叉证据，先补最薄弱的环节。
DROP
参考分低于 55，暂缓投入。
BLOCK
合规或 IP 风险 ≥ 4，或保守贡献毛利低于 20%。高热度不能抵消风险。

“已收录”包含历史资料；“近期可用”只统计通过时效、地区和排除检查的记录。“未采集”与“未记录”都不等于数值 0。30 天和样本数量也是初始研究规则，不是统计充分性的证明。证据覆盖只是研究准入，不是成功概率。

使用流程从候选对比到证据复核
  1. 先核对方向为什么入池

    先确认客群、问题、入池线索和还没排除的替代方向，再看参考分、利润假设与风险。候选池不完整时，不把最高分解释为市场最优。

    查看研究方向对比
  2. 核对原始样本

    按候选、平台和日期检查商品价格、评价数与来源，区分历史样本和近期信号。优先补齐评论、市场地区或正式报价的缺口。

    查看市场样本
  3. 补证据，再调整假设

    本地后台可导入 JSON/CSV，排除无关记录，并人工更新评分与成本。Monid 采集须先配置密钥、检查接口和报价、批准本次调用，再核对返回结果并导入。

    进入本地采集
  4. 小样验证，而非直接放量

    证据、利润和风险全部通过后，再评估 20–50 件测试。复核样品、供应商规格、运输和权利链；持续记录退款率、广告后毛利与售罄周期。

公开网页与本地后台

GitHub Pages 是发布时的数据快照，只提供浏览、筛选和比较；它不会实时抓取，也不能保存修改。本地后台负责编辑、导入与付费采集。更新数据后需重新提交和发布，公开网页才会刷新。

密钥与私有采集任务不随 Pages 发布；已导入的证据原文会进入公开快照，发布前须去除个人信息和保密报价。费用预估不是账单硬限额，真正的预算限制应在 Monid 工作区设置。

  1. P0

    候选发现与入池依据 待建立 · 协作

    先确定目标客群、使用问题、经营约束和搜索范围，再列出候选全集，记录每个方向为何进入、哪些替代方向被排除；补齐截图/榜单原始证据，避免只研究先选中的一个方向。

    完成标准：每个候选有可追溯入池理由与反证条件，多个方向按同一地区、关键词、排序与样本范围采样；明确平台排序、广告及缺失数据偏差。API 采集不能代替这一步。

  2. P0

    API 与采集预算 待配置 · 你

    使用 Monid 需要账号、API key、可用额度和工作区预算/单次限额确认。只在本机设置密钥，不写进网页或 GitHub；本地开关开启不代表已核验远程限额。

    完成标准：成功检查一个可用接口，人工批准一次小样本调用，核对 run ID、结果及实际费用。也可以先用人工 CSV 推进，Monid 不是唯一入口。

  3. P0

    近期新加坡需求证据 待采样 · 协作

    先验证线缆整理套装的 SG 配送、同规格价格、近期评论和内容场景。不能预设聚合 API 一定有 SG 数据；接口受限时改为合规人工采样。

    完成标准：有可复核的市场、日期、来源与原文，覆盖至少两个需求平台；达到现有最低研究门槛后仍需检查样本偏差。

  4. P0

    真实成本与税务口径 待核实 · 你 / 供应商 / 财税顾问

    确定销售平台、经营主体与履约方式，获取同规格三家报价，补包装、运输、末端履约、平台/支付费用、退款及 GST 处理。

    完成标准：每项成本有来源，重算悲观/基准/乐观贡献利润；统一除以 1.09 的假设经核实或修订，不把贡献利润当净利润。

  5. P0

    合规、授权与样品 待审核 · 你 / 专业机构

    按具体 SKU 核对材质、认证、进口要求、标签与知识产权；电池等特殊品类单独确认运输条件。

    完成标准：样品与文件可追溯，阻断项得到实质解决；不能用调低风险分代替审核。

  6. P1

    模型敏感性与真实结果验证 未开始 · 开发 / 运营

    先比较等权和当前权重，对权重浮动后重新归一化；合规审核通过后，再记录小批量订单、广告、退款和净回款。

    完成标准：有排序稳定性分析及测试前评分与测试后经营结果；积累足够的跨商品、跨周期数据后再校准，不用一单成功证明模型有效。

  7. P1

    持续更新与公开发布 待建立 · 协作

    建立每周采样、证据复核和发布记录；当前 Pages 是静态快照，不会自动刷新外部数据，定时采集尚未启用。

    完成标准：记录最后采样与发布日，过期或失败可追踪；公开数据脱敏，并有每轮费用核对，不自动扩大采集预算。
