# 选品数据采集 SOP

## Monid 小样本验证

平台：[Monid](https://monid.ai/)。聚合接口不是数据质量保证；Amazon、YouTube、Reddit、TikTok 等需要动态检索后检查地区、字段、价格和健康状态，不能预设固定接口或捏造响应。付费 API 的授权也不等于获得数据再发布许可。

首轮优先研究 `cable-sleeve`，用以下顺序控制成本：

| 任务 | 接口发现查询 | 首轮样本 | 需要回答的问题 |
|---|---|---:|---|
| 商品价格 | `amazon product prices` | 同规格 5 个商品 | SG 配送可用吗？低价是否只是单件而不是套装？ |
| 用户评论 | `amazon product reviews` | 最近评论 5-10 条 | 胶粘失效、尺寸不合或安装难度是否重复出现？同时保留正向评价 |
| 内容场景 | `youtube search videos` | 5 个视频 | 用户演示的是哪种使用场景？全球兴趣不当本地成交 |
| 社区讨论 | `reddit search posts` | 5 条讨论 | 痛点是否真实重复，是否已有更便宜替代？ |
| 供应链 | `web search` | 同规格 3 家候选供应商 | 公开挂牌不是正式报价；另行询价核实包装、MOQ、运输 |

1. 在候选证据区选定产品，进入数据采集，检索并检查具体接口的 Schema、计费、备注和地区参数。
2. 按 Schema 填入原生 `input` JSON；不把“接口检索词”当成商品搜索参数。一次一个搜索词/URL，首轮限制 5-10 条。
3. 检查报价。只支持明确的 `PER_CALL`、简单 `PER_RESULT` USD 计费。未知、按时间或复杂矩阵计费不在本地执行。
4. 配置工作区预算和单次运行限额后，逐次批准执行。本地估价不能阻止供应商按不同单位计费；真正的限制由 Monid 工作区控制。
5. 异步任务用刷新按钮读取状态，不再次执行。`UNKNOWN`/`SUBMITTING` 需要到控制台核对；`BLOCKED` 为终态，不会自行恢复，先确认哪项控制阻止运行。不得盲目解除预算保护。
6. 检查 `status` 和 `providerResponse.httpStatus`，只有 `COMPLETED` 且供应商成功才允许映射。原始任务和费用信息保存在 `data/raw/monid/`。
7. 预览字段映射、人工核对每条证据后导入。标签是人工分析结果，系统只计数，不声称进行了自动情感分析。

### 证据字段

可通过本地页面导入 JSON 数组或 UTF-8 CSV；页面提供 CSV 表头模板。单次最多 1000 条，HTTP 请求最多 2MB，文件选择最多 1.5MB。验证失败整批不写入。

| 字段 | 要求 |
|---|---|
| `product_id` | 必须来自候选 CSV |
| `platform` | 原始平台，如 `amazon`、`youtube`；不要填聚合商 Monid 以冒充独立需求平台 |
| `kind` | `listing` / `review` / `social` / `supplier`；后者仅正式报价，不用于公开挂牌 |
| `market` | SG、US、CN、GLOBAL 等；无法验证时使用 UNKNOWN，不自动推断为 SG |
| `observed_at` | 原始观察日期或 ISO 时间戳，不是导入日期 |
| `published_at` | 可选来源发布日期；评论/内容尽量提供，避免旧内容因今天采集变成新趋势 |
| `url` | 可核对的 HTTP(S) 原始来源，不允许含账号密码 |
| `text` | 原始证据或保留原指标的 JSON 文本，不能把评分数当成评论原文 |
| `source_id` | 建议保留平台记录唯一 ID；不同评论不能共享商品 ID |
| `title` | 可选 |
| `tags` | 人工短标签，使用 `\|` 分隔；例如 `adhesive\|installation` |
| `collection_id` | 从 Monid 预览导入时自动关联本地任务 |
| `excluded` | 可选布尔值；排除的证据保留但不参与覆盖检查 |

去重以产品、平台、类型和来源 ID 为准；无 ID 时商品/报价使用来源 URL，评论/社媒使用 URL 加规范化原文。去掉 URL 的 UTM 和 fragment。重复证据不增加计数；同日更正或更近的观察可更新记录。该存储是每条证据的最新有效状态，历史版本以原始文件和 Git 为准，不是完整时序数据库。

### 映射返回数据

使用 JSON Pointer：如 `output` 是 `{"items":[{"review":{"body":"..."},"link":"https://..."}]}`，数组路径填 `/items`、原文字段填 `/review/body`、URL 字段填 `/link`。`output` 本身是数组时数组路径留空。可选记录 ID 和发布日期按实际字段填写，缺失字段会拒绝预览，不会静默丢弃记录。

市场默认 UNKNOWN，日期不自动填今天。先核对 SG 地区与配送目的地，再选 SG。不要将 API 密钥、私人联系方式、完整用户档案、机密报价或大段受限内容导入可能公开的 Pages 数据。需要保留机密原始资料时使用本地 `data/raw/`，公开证据只留获准发布的必要摘要和来源。

## 每周采样表

统一用 `data/candidates.csv` 的 `product_id`，原始文件放入 `data/raw/YYYY-MM-DD/`（原始目录默认不提交）。每条记录必须有地区、采样时间、URL/关键词、原始指标和截图或 CSV 文件名。

| 来源 | 操作 | 最少记录 | 用途 |
|---|---|---:|---|
| Amazon SG Best Sellers | 进入相关类目记录前 20、价格、评分数 | 20/类目 | 本地成交代理 |
| Shopee SG / Lazada SG | 无登录窗口搜索固定英文词，记录自然结果 | 20/词/平台 | 价格带、销量显示、竞争密度 |
| Google Trends | 地区 SG；近 12 月和 90 天；导出 CSV | 2 窗口/词 | 趋势、季节性、加速度 |
| TikTok Creative Center | 地区 SG；近 7/30 天；按 Reach、CTR、2s/6s 分别观察 | 20/类目 | 内容与商业意图 |
| Meta Ads Library | 国家 SG；搜索 3 个同义词；记录活跃广告主和首投日期 | 3 词/方向 | 广告主重复与持续性 |
| 1688 | 固定规格询价，不能混用不同材质/尺寸 | 3 家/候选 | MOQ、成本、重量、交期 |

## 防止数据误读

- 不把评论总数当近期销量；同时记录最近 30/90 天评论增量。
- 不把 Google Trends 的 100 当绝对搜索量；同批次比较，保存关键词组合。
- 不把广告曝光当成交；Reach/播放留存与 CTR/CVR 分开记录。
- 不把一个平台的榜首外推为新加坡全市场；至少两个独立层级交叉验证。
- 不抓取登录后、验证码后或 robots/条款明确限制的内容；改用人工记录或官方导出。
- 不采购带品牌名、角色形象、专利结构暗示但无法提供授权链的商品。

## 供应商询价模板

```text
目标市场：新加坡。请按同一规格回复：
1. 20 / 50 / 200 件含税单价与 MOQ
2. 单件净重、含包装毛重、外箱尺寸与装箱数
3. 打样费、交期、补货周期、瑕疵率与赔付条款
4. 材质报告、适用认证、电池型号/MSDS/UN38.3（如适用）
5. 是否涉及商标、外观、专利或角色授权；请提供权利链文件
6. 中性包装与英文标签能力
```

## 更新流程

1. 将平台原始记录保存并写明日期，通过证据面板导入，检查重复、地区、过期和痛点标签。
2. 根据核对后的证据人工更新候选行的评分与真实报价；系统不从社媒热度自动推断成交或提高利润。
3. 运行 `PYTHONPATH=src python3 -m sg_product_research.cli`。
4. 查看 `generated/ranking.md`，只为 `TEST` 项提交采购审批。
5. 对每个 `TEST` 项执行 HS/CA Product Code Checker，并把确认结果归档。
